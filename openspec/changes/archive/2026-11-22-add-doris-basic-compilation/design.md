## Decisions
Use Cube's pinned BaseQuery/MySQL conventions for common templates, backtick escaping and positional question-mark parameters. Doris SELECT uses LIMIT count OFFSET offset (not Presto OFFSET before LIMIT); reject offset without limit. No time or pattern templates are provided. Conservative initial envelope: exactly one cube, no joins or time-typed dimensions in the model, no timeDimensions, and only equals/notEquals/gt/gte/lt/lte/set/notSet filters (including recursive user/security groups). Everything outside returns Unsupported without SQL, after model validation. Filtered measures, formulas and segments use the existing B0 planner.
Alternatives: enabling all MySQL templates would imply untested Doris coverage; waiting for full B0 blocks a useful independently testable slice. This slice does not transfer the seed's full-matrix B0-DORIS-001/002 requirements or claim engine execution.
